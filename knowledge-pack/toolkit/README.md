# Toolkit — dynamic tools & keys catalog

كل ما يحتاجه الوكيل لمعرفة الأدوات المثبتة والمفاتيح والحصص موجود هنا.
الكتالوج يتولد تلقائياً بواسطة `toolkit-scan.sh` — لا تعدّل `inventory.yaml` يدوياً أبداً.

## البنية

```
toolkit/
├── inventory.yaml      ← الكتالوج المولّد (المفاتيح مقنّعة فقط)
├── keys/               ← ملفات مفاتيح API (ملف لكل خدمة، صلاحيات 0600)
├── tools/              ← بطاقات قدرات الأدوات المثبتة
└── toolkit-scan.sh     ← الماسح: يجدّد الكتالوج
```

## إضافة مفتاح جديد (بدون إخبار الوكيل)

1. احفظ المفتاح في ملف: `printf '%s\n' 'KEY' > ~/.hermes/toolkit/keys/<service>.key`
2. أقفل الصلاحيات: `chmod 600 ~/.hermes/toolkit/keys/<service>.key`
3. حدّث الكتالوج: `bash ~/.hermes/toolkit/toolkit-scan.sh`
4. انتهى — الوكيل سيراه في `inventory.yaml` (مقنّعاً) ويقرأ الملف عند الحاجة.

أو اطلب من الوكيل مباشرة في topic ⚙️ الإعدادات ("أضف مفتاح X" / "ثبّت أداة Y")
— مهارة `asset-ingestion` تفعل نفس الشيء تلقائياً وتحدّث الكتالوج.

## إضافة أداة جديدة

1. ثبّتها بحيث تكون على PATH (apt، pipx، uv tool، تنزيل إلى /usr/local/bin...)
2. شغّل الماسح (أو انتظر التحديث الدوري) — يكتشف الملفات التنفيذية تلقائياً.
3. اختياري: أضف بطاقة قدرات في `tools/` ليعرف الوكيل الاستخدام والحدود.

## قواعد
- أي ملف مفتاح يجب أن يكون 0600 — الماسح يتجاهل الملفات المقروءة للجميع.
- لا تضع هذه الملفات في git أبداً.
- المفاتيح الخاصة بأدوات محددة (subfinder، vulners، ngrok...) تبقى في مواقعها الأصلية — الماسح يقرأها تلقائياً.
