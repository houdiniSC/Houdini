# Asset Ingestion — add tools, keys & assets dynamically

Run when: the owner asks in the **⚙️ الإعدادات** topic to install a new tool,
add/update an API key, or receive files/assets (e.g. "ثبّت أداة X",
"أضف مفتاح", "add key", "add tool", "استلم ملفات"), or attaches files there.

From any other topic: refuse politely and redirect to ⚙️ الإعدادات.

## One registry, one catalog

Everything the agent knows lives under `~/.hermes/toolkit/`:

| Type | Saved to | Listed in |
|---|---|---|
| API keys | `toolkit/keys/<service>.key` (0600) | `inventory.yaml` → `extra_keys` |
| Tools | PATH + optional card `toolkit/tools/<name>.md` | `inventory.yaml` → `tools` |
| Assets (files, wordlists, ovpn, configs) | `toolkit/assets/<name>` | `inventory.yaml` → `assets` |
| Manifest + backups | `toolkit/assets/manifest.json` + `toolkit/backups/` | — |

`inventory.yaml` is generated by `bash ~/.hermes/toolkit/toolkit-scan.sh`
and is the ONLY catalog the agent reads first (see SOUL.md). After any intake,
re-run the scan so every future session sees the change.

## Procedure

1. **Tool intake** ("ثبّت أداة X"): pick the standard install path — `apt` for
   system packages (`sudo apt-get install -y <pkg>`), `uv tool install` /
   `pipx` for Python CLIs, GitHub release binary → `/usr/local/bin` for
   single-file tools. Verify with `command -v <tool>` and capture the version.
   Optionally write a small card `toolkit/tools/<tool>.md`
   (purpose, usage, limits).
2. **Key intake** ("أضف مفتاح X" or `service: key`): parse service name and
   key (accept `NAME=value`, `service: value`, or context + key). Save to
   `toolkit/keys/<service>.key` with `chmod 600`. If the service has a
   tool-specific location (subfinder, uncover, ngrok, wpscan, vulners, nvd),
   also write that tool's own config file so it works immediately. Never echo
   the key back — confirm masked only.
3. **Asset intake** (attachments or "استلم ملفات"):
   - `.ovpn` → `~/vpn-profiles/<sanitized-name>` (chmod 600) — see `vpn-egress`.
   - Any other file/zip → `toolkit/assets/<sanitized-name>` (chmod 600 if it
     looks secret), unzipping zips first.
   - Copy every received file to `toolkit/backups/` and record it in
     `toolkit/assets/manifest.json` (name, sha256, received timestamp, backup
     path — never the content of secrets).
4. **Refresh** the catalog: `bash ~/.hermes/toolkit/toolkit-scan.sh`.
5. **Confirm** in one line — names only, e.g.
   "v أضفت أداة httpx (v1.10.0) + مفتاح shodan — الكتالوج محدّث."

## Self-heal (later sessions)

At session start, or before using any asset, compare disk with
`toolkit/assets/manifest.json`; restore missing files from
`toolkit/backups/`, re-run the scan, and report the restoration in one line.
If a backup is also missing, report to ⚙️ الإعدادات what is gone — never
block silently.

## Guards

- Settings topic + owner only.
- No memory writes — the toolkit registry + `inventory.yaml` are the source
  of truth.
- Never print keys, passwords, or full file contents.
- If a parse fails, ask for the format once; do not guess.
- Always finish with `toolkit-scan.sh` so the catalog and disk agree.
